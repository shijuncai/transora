## 3. 七项检查怎么算

| ID | 检查 | 实现 | 判据（默认） |
|---|---|---|---|
| R1 | 非文本区保真 | **双层**：① 掩膜外逐像素差（精确）② 结构连通域差（抗几何误差） | ②为硬门禁：丢失 ≤ max(64px, 结构像素×2%) |
| R2 | 文本溢出 | 每行排版框与分配框的四边差 + 未落版行数 | > 0.5pt 即报 |
| R3 | 遮挡 | 墨迹框相交面积 > 1pt² **且纵向重叠 > 45%** | 0 对 |
| R4 | 字形缺失 | 逐字查字体 cmap（`PDFTextMetrics.missingScalars`） | 0 个 |
| R5 | 内容完整性 | 意图文本 vs 落版文本（去空白比较）+ 占位符一一对应 | 0 处截断 |
| R6 | 版面相似度 | 先盒子模糊抹掉字形，再算 SSIM（降采样 2×） | ≥ 0.86，仅警告 |
| R7 | 阅读顺序 | 左沿聚类分栏 + 栏内自上而下；只比段落块 | 0 逆序 |

### 3.1 为什么 R1 要两条腿

掩膜法的语义最精确：**IL 框以外的像素必须一模一样**。但它依赖 IL 框与渲染墨迹对齐。
这一版在幻灯片文档上实测到 3 万像素的假差异，当时的结论是「IL 坐标偏了 80pt」——
**这个结论在 P5 被推翻**：真正错的是渲染器（`getDrawingTransform` 不缩放，页面被 1:1 画在画布中央，
而 `pixelX/pixelY` 按 `dpi/72` 换算）。修好渲染器后，IL 框与真实墨迹、与 PDFKit 的
`selection.bounds` 三者的吻合度在 1px 以内（见 `stage-p5-productization.md`）。
**保留两条腿的理由没有变**：掩膜法永远依赖 IL 的质量，而结构法不依赖——
它是对「IL 错了」这件事的兜底，只是这次先被一个渲染 bug 触发了。

结构连通域法换了个不依赖 IL 的问题：**把字丢掉，只比结构**。

```
二值化 → 去掉面积 < 240px 的连通域（汉字/标点/下划线都在这一档）→ 3×3 膨胀 1px → 双向比
```

文字怎么换都不影响它；图片、色块、表格线少一个像素就报。代价是「8pt 以下的小图标消失」抓不到，
这个代价是明码标价的，写在 `PDFStructuralDiff` 的文档注释里。

实测（409 页书，抽 20 页，恒等排版，**P5 修正渲染器后重跑**）：20 页结构丢失全为 0。

## 4. 修复回路

```
排版 → 渲染 → 分析 ─┬─ 通过 → 交付
                    └─ 失败 → 段落级指令 → 再排版 → 再分析（≤2 轮）→ 仍失败：交付 + 清单
```

四类指令，**单调**（只会越来越保守）：

| 指令 | 触发 | 动作 |
|---|---|---|
| `shrink` | R2 溢出 / R3 遮挡 | 该块字号下限降到 `当前×0.9`（最低 5pt），允许再向下扩 15% |
| `avoidSide` | 压图/压表 | 禁止向右、向下扩框（扩只会更糟） |
| `revert-to-source` | 已到 5.6pt 仍放不下 | 该块回落原文（原文当初就在这个框里） |
| `reflow-page` | R5 截断 / R7 逆序 | 整页重排 |

「只重写受影响页」怎么保证：修复只改**参数**，不动算法；字体子集首轮就收进原文+译文全部字符，
所以 CID 映射跨轮稳定。每轮对账 `contentHash`：上一轮已通过的页若内容流变了，记进
`unexpectedPages` 并强制重查。实测伪译文 40 页闭环第 1 轮只有 10 页内容流变化，全部是修复页，
`unexpectedPages` 为空。

## 6. 这一阶段抓到的真问题

### 6.1 会「静默丢字」的页（已修）

有的文本算子我们能删、但读不出来：`PDFTextExtractor` 在字体/CMap 解析失败时静默 `return`，
于是既没有 run、也不会被重画 —— 一旦驱逐就是**内容消失**，而且报告里一切正常。

真实例子：16:9 幻灯片里的思维导图，标签用一种读不出 CMap 的字体，整页 105 个文本算子只解出 3 行。

处理：`unreadableTextOps > 0` 的页判为不可译，整页保持原样并列入 needsReview。
**不做「只翻译读得懂的段」** —— 驱逐是整页的，读不懂的那部分删了就画不回来。

### 6.2 「IL 坐标偏 80pt」——**诊断错了，已在 P5 推翻**

当时的现象：幻灯片文档（`960×540`）上 `--overlay` 的红框落在标题上方的空白里，
R1 结构比对报 3393 px 丢失，于是判定「P2 的 CTM 追踪有缺陷」。

P5 复查时发现三件事叠在一起：
1. `PDFPageRenderer` 用 `CGPDFPage.getDrawingTransform(..., preserveAspectRatio: true)`，
   而它在 macOS 27 上**根本不缩放**：1920×1080 的目标里，页面被 1:1 画在正中（`a=1, tx=480, ty=270`）。
   位图是 2× 尺寸，`pixelX/pixelY` 也按 2× 换算，但页面像素只占中间那一块 —— 掩膜、探针、裁剪全部错位一倍。
2. `pdf-structure --overlay` 画框时把 `yTop` 当下边用，`height` 算成负数被 `max(0.5, …)` 兜住，
   **所有框都画成一根细线**，看起来就像「框整体偏上」。
3. 我的两个临时诊断工具（裁剪、行带统计）抄了同一个 `getDrawingTransform`，所以「印证」了错误结论。

修掉渲染器与叠加图之后：IL 标题框 `(29.6,465.6)-(495.7,521.1)`、PDFKit `selection.bounds`
`(29.7,465.6)-(495.7,521.1)`、渲染墨迹行带 `472…514`，三者吻合；同一页 R1 结构丢失 `3393 → 0`。

**教训**：当「几何对不上」时，先证自己的尺子是准的。像素级判据的两个输入
（渲染、IL）里，渲染器是我自己写的，本来就该先被怀疑。

### 6.3 三处误报（已修，都已写进注释防止回退）

| 误报 | 根因 | 修法 |
|---|---|---|
| R2 每段都「溢出」0.24em | 墨迹框用 hhea ascent（1.16em），排版用 clamp 到 0.92em | 墨迹框改成与排版同一套模型 |

## 8. 结论

- **R1 从「结构性不可能变」升级为「可证的 0」**：409 页真实文档抽 20 页，
  16 页结构丢失严格 0 px、3 页 7–13 px（容差内），1 页 248 px 超限并已列清单——不掩盖。
- **R2/R3/R7 的误报是从 213/92/858 降到 0/2/0**（恒等排版，20 页抽样） —— 这三组数字是这一阶段最花时间的部分，
  每一个都对应一条写进代码的注释。
- **闭环跑得起来也有边界**：40 页极限输入下，6 页自动修好、11 页明说修不好。
  没有「静默降级」这条路。
- **P4 顺手抓到两个上游缺陷**：会静默丢字的页（已修）、翻转坐标系的 IL 偏移（转 P5）。
  后者如果不做像素校验，会一直藏到用户手里。
