# P3 阶段报告：排版（把译文写回原版式）

> 日期：2026-11-23
> 结论：**P3 完成**。`hymnctl pdf-typeset` 能把译文按原版面写回 PDF，图片/矢量逐字节不变，
> 测试 356 → **384**，release 零警告。
> 一句准确的概括：**能写、能读、能排；但「排得好看」在密集表格和目录页上仍有明确边界。**

---

## 1. 这一阶段到底做了什么

P3 的输入是 P2 的 IL（块 / 单元格 / 插图框），输出是「单语同版式 PDF」。中间要回答三个问题：

1. **这段话有多宽？** —— 度量必须和阅读器的绘制算法一致，否则「算得下、画出来溢出」；
2. **从哪里断行？** —— 中文有禁则，西文有词边界，数字不能和单位分家；
3. **放不下怎么办？** —— 有明确的优先次序，不能随手缩字，更不能叠字。

投放顺序（代码里写死，改它就是改可读性策略）：

```
① 原字号 + 原框
② 压行距 1.4 → 1.25 → 1.1
③ 缩字号（0.05 步进，≤0.6 后 0.1），下限 max(6pt, 页面 P25 × 0.8)
④ 扩框：先向右（同栏空白），再向下（到障碍物/页边距）
⑤ 出口：≤2 行 inline-note → 长溢 page-note → 同页 ≥2 段长溢 page-reflow
```

**② 放在 ③ 之前是刻意的**：压行距只是变紧，缩字号是直接变难读。BabelDOC 是先缩字号，
这里反着来，因为「同页字号一致」比「行距宽松」更影响观感。

## 3. 三条不变量（任何一条破了都算 bug）

### 3.1 不丢字

驱逐是**整页级**的：一旦删了 `Tj/TJ`，页面上所有文字都没了。所以「不画」= 内容消失。
引擎对三类文字分别处理：

| 来源 | 处理 | 报告字段 |
|---|---|---|
| 段落块 | 正常排版；无译文时**重画原文** | `keptOriginal` |
| 表格单元格 | 就地排；译文放不下且原文放得下时**回落原文** | `cells` |
| 没被归进块/表的 run | **按原坐标重画**（宁可观感不一致，也不丢） | `orphanRuns` |
| 碎片块（`*`、`†`、7pt 宽的符号） | 钉住，不参与排版 | `pinned` |
| 等宽字体块（代码） | 钉住，**不翻译** | `pinnedCode` |
| 目录点线块 | 钉住（点线无法重建，译长就错位） | `pinned` |
| 落在表格纵向带内的块 | 钉住（P2 漏检列时，这些其实是单元格文字） | `pinnedNearTable` |

最后三条是这一阶段**新增的保守策略**。它们的共同逻辑：**叠字比不翻译更糟**。

### 3.2 不动图

只替换内容流与页面资源字典，图片/矢量对象原字节不动。661 页实测：
**401 张图 SHA-256 全部相同**；40 页：4 张全部相同。

### 3.3 不静默降级

缺字、溢出、相交、不可译页，全部进报告并标 `needsReview`：

```
溢出      7 行
跳过      第 2 页（不可译/无内容）
缺字      3 个：U+F0A8 U+F0B4 U+F0B7
⚠️ 需人工复核的页：…
```

## 4. 实测数据

### 4.1 性能（release / M3 Pro）

| 文档 | 页数 | 块 | 耗时 | 输出增量 |
|---|---|---|---|---|
| Paxlovid 说明书 | 40 | 386 | **379 ms** | +684 KB（含 2 个字体子集） |
| Python 核心编程 | 661 | 11,202 | **4.6 s** | +3.3 MB |

吞吐约 **140 页/秒**（含读结构、驱逐、排版、字体子集化、写回）。
其中结构提取占大头（P2 实测 1.66 s / 661 页），排版本身约 3 s。

### 4.2 投放分布（661 页，模拟译文 = 原文截断到 50%）

| 档位 | 块数 | 占比 |
|---|---|---|
| fit（原样放下） | 6,374 | 98.9% |
| shrink（压行距/缩字） | 293 | 4.5% |
| expand（扩框） | 3 | 0.05% |
| 溢出 | 0 行 | — |

shrunk + expanded 之和大于 fit 的缺口，是因为表格单元格不计入块统计。
**结论：真实译文（缩短或等长）几乎全部走 fit，不会牺牲可读性。**

### 4.3 压力测试（伪译文 = 每块加「【译文示例】」前缀，故意变长）

| 指标 | 40 页 | 661 页 |
|---|---|---|
| 溢出行 | 14 | 204 |
| 整页重排页 | 4 | 104 |
| 相交对 | 0 | 22（16 页） |

伪译文是**对抗性**输入：每个单元格、每个标题都凭空多 6 个字。真实翻译不会这样。
它的价值是证明「极端膨胀时链路不崩、且有明确出口」，不代表日常质量。

### 4.4 结构提取的连带修正

P3 修了 P2 的一个结构缺陷：**行区间交错的块**。缩进启发式偶尔把一段拆成两块，
行序变成 495 → 479 → 464，排版时前一个块会铺满整框、压住中间那个块。
新增 `PDFParagraphBuilder.mergeInterleaved`，判据是「A 有行在 B 之上、也有行在 B 之下且横向重叠」，
两栏并排不满足该条件，不会误合。661 页里合并掉 2 个块，消除了第 40 页的相交。

## 5. 这一轮踩到的五个坑

### 5.1 断行边界算错一位（最严重）

贪心循环写成「累加到溢出为止」，然后把**溢出后的位置**当断点，导致**每行多塞一个字**：

```
maxWidth 40pt, 12pt 中文字 → 一二三四 (48pt)   ← 超了 20%
```

整页右边缘被撑出去，两栏互相压。修法：先算出「真正放得下的最大字符数」，再回扫合法断点。
这个 bug 在截图里表现为「文字好像贴着栏线」，很容易被当成「差几个点无所谓」放过去。

### 5.2 字号下限被浮点误差跌破

0.05 步进累减得到 `5.9999999999999964pt`，测试抓到了。虽然只差 3e-15，
但「不低于 6pt」是承诺。修法：`size = max(floor, base * scale)`。

### 5.3 用 `block.column` 给重排分组

`ILBlock.column` 只是 P2 分栏时的**组序号**，跨栏长行会被分成独立组，
组序号与空间顺序对不上。第一版重排用它分组，结果两个组占同一片横向区域，互相压。
修法：按 x 区间聚类得到视觉栏，且**排布时用矩形碰撞**而不是「每栏一个光标」。

### 5.4 栏右边界被「通栏块」带偏

用「横向重叠比例」判定同栏，页脚那种横贯整页的块会把左栏右边界拉到整页宽，
左栏文字直接压到右栏上。修法：改判据为「左沿相近（±24pt）且宽度不超过可用宽度的 85%」。

### 5.5 行内注从「扩后的底边」开始排

块向下扩框后，扩出来的区域已经贴到下一段；再从扩后底边往下排行内注，必然压字。
修法：注释起点取 `min(扩后底边, 原底边)`，且高度不足时改走页脚注。

## 6. 明确的边界（不要当 bug 修）

1. **合并单元格**：P2 一律 1×1，P3 无法知道哪几格是合并的，跨格文字会被拆到相邻格；
2. **无线表格**：只认矢量线，靠底色/留白分区的表检不出，那些文字会当正文排；
3. **扫描件**：不做 OCR，`translatable=false` 的页整页跳过（保留原文）；
4. **竖排**：未处理；`/Rotate 90` 不校正阅读顺序；
5. **代码块字体**：钉住不译，但用宋体重画（包内没有等宽字体），行内列对齐会偏移，
   行首缩进仍然正确；
6. **目录点线**：不重建，整块钉住；
7. **3 个私用区码位**（U+F0A8/B4/B7，来自符号字体）画不出来，已在报告里列出；
8. **不能自动开新页**：一页排不下时进报告，不插页（插页要改页树，属 P5）；
9. **孤立的项目符号**：符号是独立 run，段落被移动时它按「最近块」跟随；
   跟随判据是横向间隙 ≤24pt，跨栏的极端情况可能跟错。

## 7. 与 P4 的接口（已经留好）

P3 输出给 P4 的东西，都是可计算的：

| 字段 | 含义 | P4 用途 |
|---|---|---|
| `pages[].overlaps` + `overlapPairs` | 计划矩形相交的对数与 id（带坐标） | R3 遮挡检查的起点 |
| `pages[].overflowLines` | 放不下的行数 | R2 溢出 |
| `pages[].overflowPairs` | 相交块 id | 段落级修复指令的定位 |
| `missingScalars` | 缺字码位 | R4 缺字 |
| `placeholderRejected` | 占位符损坏而回落原文的块数 | R5 |
| `needsReviewPages` | 需人工复核的页 | 报告与 UI 提示 |

P4 只需要做像素级校验（R1/R6）和修复回路，不需要重新理解版面。

## 8. 复现命令

```bash
# 伪译文（压测排版，不是翻译结果）
hymnctl pdf-typeset in.pdf out.pdf --pseudo

# 用真实译文映射（键 = pdf-structure --json 导出的 id，带页码前缀）
hymnctl pdf-typeset in.pdf out.pdf --translations map.json --report report.json

# 单页调试
hymnctl pdf-typeset in.pdf out.pdf --page 1 --translations map.json

# 校验图片未变
hymnctl pdf-verify in.pdf out.pdf
```

译文映射的两种形态：

```json
{ "p1-p0-b0": "第一段的译文", "p1-t0:2:1": "第二行第一列的译文" }
```

```json
{ "pages": [ { "page": 1, "blocks": { "p0-b0": "…" }, "tables": { "t0": { "2:1": "…" } } } ] }
```

**键必须带页码前缀**：`ILBlock.id`（`p0-b0`）只在页内唯一，多页文档里第 1 页和第 2 页都有 `p0-b0`。
