# P9：只有横线的表格 + 整页重排的顺序与兜底（v0.8.5 build 25）

样本：`Sample/mycelia strains and sustainable growth.pdf`（9 页，Elsevier 期刊论文）
用户标注：第 5 页红框 = Table 2 里的文字显示不完整、没有换行；绿框 = 两段正文没有翻译出来。
用户的判断（「表格内的译文超出限制，导致绿框文字没翻出来」）是对的。

---

## 1. 根因：一条链上的四个环

| 环 | 事实 | 后果 |
|---|---|---|
| ① 表格没被识别 | Table 2 只画了**两条通栏横线**、一根竖线都没有，而 `PDFTableDetector` 的网格必须「横竖线求交」，各至少一条 | 这一页识别结果是 **0 张表** |
| ② 单元格变成段落 | 横线之间的行不参与表格，被 `buildBlocks` 归并成 **74 个段落块**：`TA`、`3289`、`Lipids` 各一块，框高 6.3 pt（一行） | 每块都按「段落」的重排规则走：可压行距、可缩字、可向右/向下**扩框** |
| ③ 溢出触发整页重排 | 中式译文比英文长，6.4 pt 的小格子放不下 → 溢出块进页脚注 → `pageNotes >= 2` → 整页 reflow | 正文被推进表格区域里乱流（`obstacles` 里没有这张表，因为它不存在） |
| ④ 重排丢段 | `PDFPageReflow.flow` 排不下时只 `unplacedBlocks += 1`，**不点名、也不保留原字节** | 831 字的 `Water uptake is an inherent characteristic…` 整段消失（绿框①），另一段被甩到页面最底部 |

第 5 环是叠加缺陷：整页重排时「保留原字节」是**按算子区间整体保留**的，
而表头 8 个格子共用同一个 `TJ` —— 已经翻译并重画的格子又被原样复活一遍，
页面上就是中英叠字（红框里的 `O-H拉伸O-H stretching`、`RS基板3284RS substrate`）。

---

## 2. 修法

### 2.1 `PDFRuledTable`（新增，330 行）

「横向带 + 列首对齐 + 基线行」推断：

- **带**：任意两条横线之间（纵向 16–420 pt、横向重叠 ≥ 75%），**先试最高的**——
  先试矮的会把表头切在表外，表头又变回段落块；
- **行**：按基线聚类（容差 0.5 个字高，上标/下标并进所在行；「只有一个 1–2 字碎片」的行
  再并回最近的邻行——`PO2` 的 `2` 就是这么处理的）；
- **列**：同一行里相邻 run 的间隙 ≥ 5 pt 时，右边 run 的起点就是右侧列的列首；
  起点聚类后**支持度 ≥ max(3, 行数/5)** 才认；6.4 pt 字号下词间空格不到 2.5 pt，不会把一格拆成两列；
- **否决条件**（宁可漏判，不可把正文钉住不译）：少于 3 列、少于 5 行、
  有任何 run 跨越列边界超过 8%、每行都有满格宽的长行、整句（以句号收尾）占比 > 20%、
  格子里的文字平均占满 > 85% 格宽（那是被横线夹住的正文）。

实测：第 5 页 → **12 行 × 8 列**（表头 + 11 行数据），第 4 页 Table 1 → **6 行 × 10 列**。
两页的块数从 74 / 33 降到 17 / 21，块内文字与原始版面逐格对应。

### 2.2 单元格：不扩框、按原字号、放不下退回原文

`PDFTypesetEngine` 的单元格分支改成：

- 竖直内缩从 2 pt 降到 **1 pt**（8.6 pt 的行距里留 4 pt 就等于「一行都放不下」）；
- 字号取**格子里 run 的字号中位数**（`cellFontSize`），不再用「框高 × 0.62」得出 5 pt；
- `maxRightExpandRatio = maxDownExpandRatio = 0`：单元格**不许**扩到邻列/下一行；
- 译文放不下 → 退原文；原文也放不下 → 整格保持原字节（`keptCells`），
  **绝不画半截**——「看起来翻过了、实际字被切掉」是最差的结果。

### 2.3 驱逐逻辑：删掉「重排页特例」

原来 reflow 页有一段独立逻辑：只保留「钉子块 + 页眉页脚」的算子区间，其余全删。
这段逻辑有两个毛病，正好各造成一个用户可见的缺陷：

- 没参与重排的块（表格单元格、排不下的块）被连带删掉 → 静默丢字；
- 按**算子区间**整体保留 → 共用同一 `TJ` 里已翻译的格子被复活 → 中英叠字。

现在重排页与普通页走**同一条**规则：「默认全保留 − 要重画的块/格 − 要重画的 cell」，
再对「区间同属要重画的块」的 run 走 `forcedRuns`（按原坐标单独重画）。
一句话：**除了我们要重画的，其余一个算子都不动**——reflow 也不例外。

### 2.4 重排顺序：栏内游标

`PDFPageReflow` 里每个块按原顶边放，撞到障碍物就往下推。问题是**后放的块仍从自己的原顶边开始**：
真实样本第 9 页，`[37]` 因为译文变长被顶到 y=599，它的续行留在 y=628 → 后一条跑到了前一条**上面**，
R7 报「p0-b18 应在 p0-b16 之前」，复制粘贴出来是倒的句子。

修法：同一栏里已放置的块构成**天花板**，后续块的顶边取 `min(原顶边, 最低已放置块的下沿 − gap)`。
顺序单调由构造保证（单测：`pdf-reflow` 第 188 项）。

另外：

- `Outcome.unplaced` 从「只数个数」改成**点名**（块 id 列表），调用方据此保留原字节；
- 排不下的块再跑一遍重排时**把它们的原框当障碍物**（否则新文字会压上去）；
- `pageReport.unplacedBlocks` 如实计数并标 `needsReview`。

### 2.5 缺字：变音字母退成基本字母

同一页参考文献里 `E. Çulcuoğlu, E. Ünay, F. Karaosmanoğlu` 的 `ğ`（U+011F）字体没有
（实测每次运行 `⚠️ 缺字 8 个：U+011F×3 U+011E U+015F U+015E U+0130 U+0131`），
名字直接少一个字母。`PDFGlyphFallback` 增加「拉丁变音字母 → 基本字母」映射
（`ğ→g`、`ş→s`、`İ→I`、`ı→i`、`ł→l`、`ø→o`、`ß→ss` 等，共 30 个）。
只在**字体确实画不出**时生效；装饰符号（`⇑`）仍然不换、如实报缺字。

## 4. 边界（如实）

- **表格不翻译**（沿用既有策略）：单元格译文没有走模型，`map` 里也不会有 `p5-t0:行:列` 这种键，
  所以整表按原字节保留。理由是这个样本的格子只有 6.4 pt、行高 8.6 pt，
  中文即使压到 4.5 pt 也放不下一行以上；翻出来必然是叠字或半截。
  单元格翻译通道（`typesetTables` + `cellFontSize` + 不扩框）已经修好，
  接上模型侧就能开——但那是另一个决定（要接受 6 pt 的中文表）。
- 只有**横线**的表格才走这条推断；横竖线齐全的表走原来的网格法。
  两条横线之间若是「三栏文字」，靠「跨列长行 / 整句占比 / 格内占满率」三条否决，
  单测覆盖了「正文段落不被当表格」，但极端版式（三栏、每栏都不满行）仍可能误判。
- 表格里的**合并单元格**仍不认识（每格一行，跨行合并的表会被切成多行）。
- 整页重排仍是「只下移、不开新页」；排不下的块现在会留在原位并标 `needsReview`，
  但留在原位就可能与重排后的文字挤在一起——本次样本 0 例。
- 中文译文比英文短，位置保留式排版会在段落之间留下比原文更大的空白
  （第 4、5 页双栏都能看到）。这是「不重排就保版式」的代价，不是丢字。
- 缺字兜底只覆盖拉丁变音字母；希腊/西里尔/数学符号缺字仍然如实报告（不偷偷换）。
